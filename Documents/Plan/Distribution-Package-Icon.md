# 分发项目 · 插件图标（设计草案）

## ① 入口：项目名称下方，同一张卡片

```text
‹ 返回            分发项目           构建  ⋯

╭────────────────────────────────────╮
│ 项目                      示例插件 │
├────────────────────────────────────┤
│ [缩略图]  插件图标              ›  │ ← 新增一行
│           未选择                   │
╰────────────────────────────────────╯

软件包
  …现有软件包、发布到软件源、GitHub Release…
目标
  …roothide / rootless…
```

默认自动识别，不依赖选中、构建或安装 deb。设计图标时将 256 × 256 PNG 导出到当前插件项目的 `Distribution/icon.png`。首次打开或返回分发页时，按项目根目录读取这个文件并刷新缩略图；不扫描其他图片或已安装文件。识别成功显示「已识别 · 256 × 256」，没有图标时显示「未找到项目图标」和约定路径；无效图片提示重新导出。图中的「未选择」仅表示缺少图标，「选择图片…」是旧项目的备用导入入口，导入后也保存到同一路径。两个架构共用同一图标。识别只更新本地预览，确认推送时才写入软件源的 `images/<包 ID>.png`。

## ② 预览与确认：只推图标，不发布包

```text
‹ 分发项目          插件图标

                 [图标预览]
               256 × 256 PNG
                 选择图片…

目标软件源     <已关联的 owner/repo>
目标文件       images/<包 ID>.png

             [ 推送图标到软件源 ]
```

- 从文件选图，本地等比缩放并居中，透明补边，不裁切、不拉伸；预览与最终 PNG 一致。选择和取消都不改仓库。
- 目标是设置中关联的软件源仓库，不是项目代码仓库。以实际包 ID 命名而非项目显示名；包 ID 不明确时不推送。
- 确认时列出仓库和目标文件：新文件提示「添加图标」，已有不同内容提示「替换图标」，内容相同则显示「无需更新」，不做空提交。未关联软件源时提示先关联。
- 推送仅涉及这一个 PNG；失败保留预览以便重试。现有 deb 的内容与签名不变。若要让包管理器显示图标，另需确保站点部署包含 images/，且软件包的 Icon 字段指向该文件的公开 URL。
