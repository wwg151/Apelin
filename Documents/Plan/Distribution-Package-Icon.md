# 分发项目 · 插件图标（设计草案）

## ① 入口：项目名称下方，同一张卡片

```text
‹ 返回            分发项目           构建  ⋯

╭────────────────────────────────────╮
│ 项目                      示例插件 │
├────────────────────────────────────┤
│ [缩略图]  插件图标              ›  │ ← 新增一行
│           256 × 256 PNG            │
╰────────────────────────────────────╯

软件包
  …现有软件包、发布到软件源、GitHub Release…
目标
  …roothide / rootless…
```

默认自动识别，不依赖选中、构建或安装 deb。设计图标时将 256 × 256 PNG 导出到当前插件项目的 `Distribution/<包 ID 最后一段>.png`（如 `Distribution/smartnetwork.png`）。首次打开或返回分发页时，按项目根目录读取这个文件并刷新缩略图；不扫描其他图片或已安装文件。识别成功才显示图标行；文件缺失、无效或不可读时隐藏整行，不显示占位提示。「选择图片…」可替换已识别的图标，导入后保存到同一路径。两个架构共用同一图标。识别只更新本地预览，确认推送时才写入软件源的 `images/<包 ID>.png`。

## ② 预览与确认：只推图标，不发布包

```text
‹ 分发项目          插件图标

                 [图标预览]
               256 × 256 PNG
                 选择图片…

目标软件源     <已关联的 owner/repo>
目标文件       images/<包 ID>.png

             [ 推送图标到软件源 ]
```

- 从文件选图，本地等比缩放并居中，透明补边，不裁切、不拉伸；预览与最终 PNG 一致。选择和取消都不改仓库。
- 目标是设置中关联的软件源仓库，不是项目代码仓库。以实际包 ID 命名而非项目显示名；包 ID 不明确时不推送。
- 确认时列出仓库和目标文件：新文件提示「添加图标」，已有不同内容提示「替换图标」，内容相同则显示「无需更新」，不做空提交。未关联软件源时提示先关联。
- 推送仅涉及这一个 PNG；失败保留预览以便重试。现有 deb 的内容与签名不变。若要让包管理器显示图标，另需确保站点部署包含 images/，且软件包的 Icon 字段指向该文件的公开 URL。
